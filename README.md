x86tos390x 是一个用纯 Python 写的、不需要任何第三方依赖的便携式小工具，专门做一件事：把 x86-64（也就是你平时电脑常见的 64 位 x86）机器码，静态翻译成 s390x（IBM 大型机 z/Architecture）机器码，最后还能直接打包成可以用 qemu-s390x 跑起来的静态 ELF 可执行文件。它支持的功能范围是小型 C 程序常用的那一套：整数加减乘除、与或非异或、左右移位、全局变量、数组、指针操作、普通的函数调用和返回、循环和条件跳转、基本的 write 和 exit 系统调用，还有 char、short、int、long 这些常见变量类型。内置了 10 个端到端的答案驱动测试，先在 x86 本机跑出一个参考结果，再翻译到 s390x 上跑，退出码和标准输出完全一致，10 项全部通过，翻译正确性是实际跑出来验证过的，不是纸上谈兵。它不支持的东西也提前说清楚：浮点指令、SSE/AVX、动态链接、自修改代码、非常复杂的寻址模式这些都没做，定位就是处理 gcc -O1 编出来的、只用整数和简单内存操作的小程序，做教学和研究很合适。整个项目是多文件结构，代码注释全部用超简洁的中文写的，一眼就能看懂每一步在干嘛。
 
接下来讲具体怎么用。命令行的基本格式是在项目目录下运行 ./x86tos390x.py，后面跟上输入参数、输出参数和调试参数，除了输入源必须三选一之外，其它都是可以自由组合的。先讲三个输入源，它们是互斥的，每次只能选一个。第一个叫 --hex，后面跟一串 x86-64 的十六进制字节，比如 "b8 05 00 00 00 c3"，中间用空格隔开就行，带逗号或者 0x 前缀也没关系，程序会自动忽略。这个参数适合快速玩一玩，比如你就想知道 mov eax,5 加个 ret 翻译成 s390x 是什么样，直接丢进去就能看结果。第二个叫 --in-file，后面跟一个原始二进制文件的路径，比如 prog.x86.bin，适合你手上已经有一个纯机器码文件，不想手动转成十六进制字符串的情况。第三个叫 --obj，这个是最实用、最推荐的模式，后面跟 gcc -c 编译出来的 .o 对象文件，比如 hello.o。为什么最实用？因为它会自动帮你解析 .o 里面的符号表、重定位表、.data 段的全局变量、.text 段的每个函数体，不是翻译一段孤零零的机器码，而是翻译一个完整的、有结构的对象文件，最后产出真正有意义的可执行程序。用它的标准流程就是：先用 gcc -O1 -fno-pie -fno-stack-protector -c hello.c -o hello.o 编一个对象文件，然后丢给翻译器，就能出 s390x 的 ELF。
 
然后是两个输出参数，这两个可以一起用，也可以一个都不用（一个都不用就只往终端打印，不落盘）。第一个输出参数是 --out，后面跟一个文件名，比如 out.s，它的作用是把翻译后的 s390x 汇编源文本写到这个文件里。什么时候用呢？比如你想手动研究翻译出来的每一条 s390x 指令对不对，或者想改一改再自己用 s390x-linux-gnu-as 汇编，就加上这个参数把汇编写出来。第二个输出参数是 --elf，后面跟一个文件名，比如 out.s390x，这个参数会直接帮你把翻译结果打包成一个 s390x 的静态 ELF 可执行文件，编完之后你直接 qemu-s390x out.s390x 就能跑，退出码就是程序返回的结果，这个是最常用的生产级用法，一般和 --obj 搭配。
 
再讲两个纯调试用的参数，平时可加可不加。第一个是 --list，它不需要跟值，单独写上去就行，作用是在终端打印一份 x86 指令和 s390x 指令逐行并排的对照清单，哪条 x86 被翻成了哪几条 s390x 一目了然，翻译出问题的时候第一个想到加它。第二个是 --base-addr，后面跟一个数字，可以是十进制也可以是 0x 开头的十六进制，默认值是 0。它的作用是给裸字节模式（也就是 --hex 和 --in-file）设定一个虚拟的起始地址，这样配合 --list 打印出来的地址列就会和你 objdump 看到的地址对齐，方便比对反汇编结果。
 
下面给几个平时最常用的组合方式，直接复制改改路径就能用。第一种，最快上手，就想看看一段十六进制机器码翻译出来是什么：./x86tos390x.py --hex "b8 05 00 00 00 c3"。第二种，想逐行对照 x86 和 s390x 每条指令对不对：./x86tos390x.py --hex "48 01 c8 c3" --list。第三种，想出一个能在 QEMU 里直接跑起来的 s390x ELF：./x86tos390x.py --hex "48 c7 c0 0a 00 00 00 48 83 c0 14 c3" --elf /tmp/demo.s390x，然后 qemu-s390x /tmp/demo.s390x ; echo "exit=                         ?"，你的 C 程序就这么跑到 s390x 上了，退出码和你在 x86 本机编译运行出来的一模一样。第五种，想把翻译出来的汇编保存下来慢慢研究：./x86tos390x.py --obj hello.o --out hello.s390x.s --list，这样 hello.s390x.s 里是完整的汇编，终端还会打印对照清单。最后总结一下参数搭配的规律：如果你只是快速看翻译效果，不存文件，那就只用 --hex 或者 --in-file 不加任何输出；想逐行对照就加 --list；想得到汇编源文件就加 --out 加文件名；想得到能直接在 QEMU 跑的程序就加 --elf 加文件名；翻译 gcc 编出来的对象文件就用 --obj 加 --elf 最省事，想研究汇编就 --obj 加 --out 加 --list。
